с 2026-10-15; LXC 203 выделен для e2e приложения и сборок.

Интегрированы dev `e1bbe1f` и сохранённый кандидат N-7 `5a58c8c`
(включает mesh-фазу 2 / N-6). Merge `80faf05` сохранил актуальные

N-8, часть 1 (`55afd42`): при депозите в очередь непустой recipientId
должен совпадать с владельцем. Иначе NO_PERMIT до хранения, доставки и
push. Пустой адресат остаётся допустим в capability-модели. Проверены
неверный владелец, отсутствие доставки обеим сторонам и следующая
корректная отправка в той же сессии; весь queue_addressing: 9 passed.

SEC-43: под-квота sender→recipient прямого backend теперь общая для
account- и всех device-scope. Отдельный namespace агрегатного счётчика
не пересекается с прежними ключами; он пересобирается из сообщений на
старте и меняется при записи/ack/удалении. При достижении потолка
проверяются реальные TTL, чтобы протухшие записи не держали бюджет.
Кэш FULL пары тоже общий для всех устройств; квота отдельной очереди
сохраняет свою область. Формат сообщений sled v5 не менялся.

Проверки 2026-10-15: полный `cargo test --locked -- --test-threads=2` —
483 passed, 21 ignored, 0 failed. Включены реальный Noise/TCP-сценарий
смены recipientDeviceId для обхода квоты, изоляция других отправителей,
перезапуск, освобождение бюджета после ack/TTL и области кэша FULL.
Ignored включают JetStream с внешним NATS; этот прогон не заявляет
проверку брокерной доставки. JetStream использует отдельные лимиты

N-8 реализован в кандидате (подробности ниже). Остаётся перенос схемы в

## N-8: provenance очереди

Кандидат возвращает фактически использованный `queue_id` в
`IncomingMessage.queue_id` (поле 6). Подписанный ServerConfig сообщает
`supports_queue_provenance` (поле 23) только при включённой queue-addressing.
Проверка владельца выполняется до приёма сообщения. При выключенном флаге
переданный queue_id игнорируется и не отражается в доставке.

Sled сохраняет provenance в отдельном дереве `message_queues`: запись и
удаление атомарны с телом конверта. Формат тела v5 сохраняется; старые записи
читаются с пустой provenance, без выдуманного адреса. Очистка после TTL/ack
удаляет метаданные; старт очищает оставшиеся без тела ключи. JetStream хранит
адрес в аддитивном поле 11 BrokerMessage и возвращает его при передоставке.
Старые клиенты могут игнорировать новые поля. Строгому клиенту следует
проверять возможность ноды и совпадение очереди с известным mailbox.

Проверки N-8: полный `cargo test --locked` — 486 passed, 22 ignored,
0 failed. Дополнительно на настоящем NATS 2.12.6: адрес очереди сохранён
при передоставке и удалён после ack (queue_addressing broker test).
Проверены перезапуск Sled, legacy-записи, область подтверждения, очистка
осиротевших метаданных, подпись capability и бюджет кадра с 32-байтным ID.

Полный брокерный прогон на проверенном бинаре NATS 2.12.6:
20 passed, 0 failed, 0 ignored (`jetstream_delivery --ignored --test-threads=1`).
Включены отдельные брокеры для переполнения mailbox/stream, миграции политики
старого потока, зависания и остановки брокера. При запуске нужны обе
переменные: TRUST_MESSAGE_TEST_NATS_URL и TRUST_MESSAGE_TEST_NATS_BIN.
