# Настройки без перезапуска

Лимиты и квоты ноды можно менять на работающей ноде, не разрывая
соединения клиентов. Для этого служит файл `runtime.toml`. Его пишет
оператор вручную или агент `tmnode` по заданию админки.

## Откуда берутся значения

1. Умолчания ноды.
2. `.env` и переменные окружения.
3. `runtime.toml` — он перекрывает окружение.

Путь к файлу — `RUNTIME_CONFIG_PATH`, по умолчанию
`<STORAGE_PATH>/runtime.toml`.

## Формат

```toml
# Метка от того, кто пишет файл (админка). Нода её не толкует и только
# возвращает в статусе.
version = "2026-10-19T12:00:00Z#7"

[settings]
rate_limit_send_msgs_per_sec = 50
blob_quota_per_owner_bytes = 1073741824
limit_max_connections = 2048
```

**Имена настроек.** Имя настройки — имя её переменной окружения в нижнем
регистре: `RATE_LIMIT_SEND_MSGS_PER_SEC` → `rate_limit_send_msgs_per_sec`.
Все имена, пределы и умолчания — в каталоге `src/runtime/catalog.rs`; ниже
он приведён таблицей.

**Удалённая настройка** возвращается к значению из окружения.

**Строгий разбор:**
- незнакомое имя, значение вне пределов каталога или несовместимые значения
  (например, кусок файла не влезает в `MAX_FRAME_LEN`) отвергают файл
  **целиком**;
- нода остаётся на прежних настройках, причина пишется в лог и в статус.

**Неверный файл при старте.** Нода стартует на настройках окружения:
ошибка в лимитах не должна класть ноду.

## ICE-серверы для звонков

Серверы для `GetIceServers` (server-contract.md §6.12) задаются секцией
`[ice]`. В окружении их нет: это список с секретами.

```toml
[settings]
ice_credential_ttl_secs = 7200

[[ice.servers]]
urls = ["stun:turn.example.org:3478"]

[[ice.servers]]
urls = ["turn:turn.example.org:3478?transport=udp", "turn:turn.example.org:3478?transport=tcp", "turns:turn.example.org:5349"]
secret = "…"   # static-auth-secret coturn, не короче 16 символов
```

- **STUN** — без `secret`.
- **TURN** (`turn:` / `turns:`) — обязательно с общим секретом coturn.
  coturn настраивается с `use-auth-secret` и тем же `static-auth-secret`.
- **Пределы:** до 8 серверов, до 8 URL у каждого.
- **Без секции** серверов нет: `supportsIceServers = false`, запрос
  получает `NOT_CONFIGURED`.
- **Секреты** не попадают ни в логи, ни в отладочный вывод.

## Когда изменение вступает в силу

Нода проверяет файл раз в 2 секунды и сразу — по `SIGHUP`
(`docker kill -s HUP message-service`). Дальше всё зависит от настройки:

| Когда действует | Что это значит |
|---|---|
| сразу | следующая операция любой сессии, в том числе уже открытой, видит новое значение |
| новые сессии | действует для новых соединений и сессий, живые работают со старым до переподключения |
| перезапуск | значение входит в постоянные индексы или в протокол, который клиенты кэшируют; оно применится при следующем старте, а до тех пор числится в `pending_restart` |

**Подписанный `ServerConfig`** (потолки хранилища файлов) любая сессия
получает уже с новыми значениями. Клиент, который держит старый снапшот,
увидит их после `expiresAt` или при следующем `GetServerConfig`.

## Статус

Итог каждой попытки нода пишет атомарно в `runtime.status.json` рядом с
файлом. По нему агент сообщает админке, что применено.

```json
{
  "result": "applied",
  "version": "2026-10-19T12:00:00Z#7",
  "sha256": "…",
  "at": 1792443630,
  "error": null,
  "pending_restart": ["blob_min_charge_bytes"]
}
```

`result`:
- `applied` — файл применён;
- `invalid` — отвергнут, причина в `error`;
- `absent` — файла нет, действуют настройки окружения.

Метрика `trust_message_tcp_runtime_reload_total{result}` считает
попытки. Рост `invalid` означает, что нода работает не на тех настройках,
которые ей прислали.

## Каталог

**Отправка и квоты очередей**

| Настройка | Когда действует | Смысл |
|---|---|---|
| `ttl_min_seconds` | сразу | Минимальный срок жизни сообщения: депозит с меньшим ttl отклоняется. `0` — без ограничения. |
| `quota_max_messages_per_queue` | сразу | Потолок сообщений в одной очереди (прямой бэкенд). `0` — без ограничения. |
| `quota_max_bytes_per_queue` | сразу | Потолок объёма одной очереди (прямой бэкенд). `0` — без ограничения. |
| `quota_max_messages_sender_pair` | сразу | Сколько сообщений один отправитель держит в очередях одного получателя. `0` — без ограничения. |
| `rate_limit_send_msgs_per_sec` | сразу | Отправка: сообщений в секунду на пользователя. `0` — без ограничения. |
| `rate_limit_send_bytes_per_day` | сразу | Отправка: байт в сутки на пользователя. `0` — без ограничения. |

**Сессии**

| Настройка | Когда действует | Смысл |
|---|---|---|
| `limit_max_sessions_per_user` | сразу | Одновременных сессий одного пользователя. `0` — без ограничения. |
| `session_confirm_timeout_secs` | новые сессии | Сколько нода ждёт первый кадр клиента после входа. |
| `limit_ping_per_sec` | новые сессии | Ping в секунду на соединение. `0` — без ограничения. |
| `limit_control_per_sec` | новые сессии | Управляющих кадров очередей в секунду на соединение. `0` — без ограничения. |
| `max_queues_per_user` | сразу | Очередей на пользователя — по сути потолок контактов. `0` — без ограничения. |
| `max_push_devices_per_user` | сразу | Устройств с push-токенами на пользователя. `0` — без ограничения. |

**Вход и TCP**

| Настройка | Когда действует | Смысл |
|---|---|---|
| `limit_max_connections` | сразу | Открытых TCP-соединений на ноду. `0` — без ограничения. |
| `limit_handshake_inflight` | сразу | Одновременных хендшейков на ноду. `0` — без ограничения. |
| `limit_handshake_inflight_per_ip` | сразу | Одновременных хендшейков с одного IP (за общим NAT — выше). `0` — без ограничения. |
| `tcp_keepalive_secs` | новые сессии | Простой до первой keepalive-пробы (0 — без keepalive). `0` — без ограничения. |
| `tcp_keepalive_interval_secs` | новые сессии | Интервал между keepalive-пробами. |
| `tcp_keepalive_retries` | новые сессии | Неотвеченных keepalive-проб до разрыва. |
| `tcp_user_timeout_secs` | новые сессии | Сколько записанное нодой может ждать TCP-подтверждения (0 — системное). `0` — без ограничения. |

**Хранилище файлов**

| Настройка | Когда действует | Смысл |
|---|---|---|
| `blob_max_size_bytes` | сразу | Потолок одного файла. |
| `blob_max_ttl_secs` | сразу | Потолок срока жизни файла. |
| `blob_quota_per_owner_bytes` | сразу | Квота файлов на владельца. `0` — без ограничения. |
| `blob_quota_per_pair_bytes` | сразу | Квота загрузившего в ящик одного получателя. `0` — без ограничения. |
| `blob_upload_bytes_per_day` | сразу | Загрузка файлов: байт в сутки на пользователя. `0` — без ограничения. |
| `blob_disk_reserve_bytes` | сразу | Свободное место, ниже которого загрузки получают QUOTA. `0` — без ограничения. |
| `blob_tombstone_secs` | сразу | Сколько помнить удалённый или истёкший файл. `0` — без ограничения. |
| `max_blob_sessions_per_user` | новые сессии | Одновременных сессий передачи файлов одного пользователя. `0` — без ограничения. |
| `blob_get_window_bytes` | сразу | Окно скачивания: сколько нода шлёт без подтверждения. |
| `blob_sync_every_bytes` | сразу | Шаг fsync при загрузке. |
| `blob_ops_per_sec` | сразу | Операций хранилища в секунду на пользователя. `0` — без ограничения. |
| `blob_stat_per_sec` | сразу | BlobStat в секунду на пользователя. `0` — без ограничения. |
| `blob_upload_stale_secs` | перезапуск | Через сколько брошенная загрузка удаляется (входит в индекс сроков). |
| `blob_min_charge_bytes` | перезапуск | Минимальный учётный размер файла в квотах (входит в счётчики квот). `0` — без ограничения. |
| `blob_chunk_max_bytes` | перезапуск | Потолок куска загрузки и скачивания (объявляется клиентам). |

**Сертификаты и подписанный конфиг**

| Настройка | Когда действует | Смысл |
|---|---|---|
| `device_cert_max_ttl_seconds` | перезапуск | Потолок срока сертификата устройства (0 — делегированный вход выключен). `0` — без ограничения. |
| `server_config_ttl_seconds` | перезапуск | Срок жизни подписанного конфига у клиента. |

**Звонки**

| Настройка | Когда действует | Смысл |
|---|---|---|
| `ice_credential_ttl_secs` | сразу | Срок временной учётки TURN; звонок длиннее продлевается ICE restart. |
